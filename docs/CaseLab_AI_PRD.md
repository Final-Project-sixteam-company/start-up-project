# CaseLab AI PRD

> Android 기반 AI 추리게임 / 커스텀 시나리오 플랫폼  
> 이 문서는 IntelliJ, Cursor, Claude Code, GitHub Copilot Chat 등 개발 보조 AI에게 프로젝트 의도와 범위를 전달하기 위한 PRD입니다.

---

## 0. 문서 목적

이 PRD는 CaseLab AI의 제품 목표, 사용자 경험, 핵심 기능, MVP 범위, AI 사용 원칙, Android 화면 흐름, 백엔드 요구사항을 정리한다.

개발용 AI는 이 문서를 기준으로 다음을 이해해야 한다.

```text
1. CaseLab AI가 어떤 서비스인지
2. Android 앱에서 사용자가 어떤 흐름으로 플레이하는지
3. 공식 시나리오와 커스텀 시나리오가 어떻게 다른지
4. AI 용의자 심문 기능이 어떤 원칙으로 동작해야 하는지
5. 백엔드는 어떤 도메인과 상태를 관리해야 하는지
6. MVP에서 구현해야 할 기능과 제외해야 할 기능은 무엇인지
```

## 1. 프로젝트 개요

### 1.1 프로젝트명

**CaseLab AI**

### 1.2 한 줄 정의

AI 용의자를 심문하고, 증거와 알리바이를 조합해 사건의 범인·동기·범행 방법을 추리하는 Android 기반 AI 추리게임 플랫폼.

### 1.3 제품 정체성

CaseLab AI는 단순한 AI 챗봇 앱이 아니다.

```text
AI 크라임씬 ❌
단순 AI 챗봇 추리게임 ❌
역할극 마피아 게임 ❌

AI 용의자 심문형 추리게임 ⭕
증거 카드 기반 탐정 게임 ⭕
커스텀 시나리오 공유 플랫폼 ⭕
사이버 방탈출 / 유즈맵식 추리 플랫폼 ⭕
```

사용자는 탐정 역할을 맡는다.  
AI는 용의자 NPC 역할을 맡는다.  
백엔드는 사건 그래프, 증거 해금 상태, 용의자 답변 정책, 정답, 플레이 세션을 관리한다.

## 2. 문제 정의

기존 추리게임과 크라임씬형 콘텐츠에는 다음 문제가 있다.

```text
1. 사건 하나를 제작하는 비용이 크다.
2. 한 번 범인을 알면 재플레이 가치가 낮다.
3. 실제 맵/세트장을 구현하려면 제작 난이도가 높다.
4. 플레이어가 직접 역할극을 해야 하면 재미가 유저 연기력에 좌우된다.
5. 온라인 랜덤 매칭은 트롤, 잠수, 스포일러 문제가 발생한다.
6. 단순 AI 챗봇 방식은 사건 일관성이 깨질 수 있다.
```

CaseLab AI는 다음 방식으로 문제를 해결한다.

```text
1. 유저는 탐정 역할만 한다.
2. AI가 용의자 NPC를 담당한다.
3. 맵 탐색 대신 현장 정보, 증거 카드, 타임라인, 심문 UI로 조사감을 만든다.
4. 공식 시나리오와 유저 커스텀 시나리오를 모두 제공한다.
5. 유저가 직접 시나리오를 만들고 공유할 수 있다.
6. 사건은 Case Graph 구조로 관리해 일관성을 유지한다.
```

## 3. 제품 목표

### 3.1 1차 목표

Android 앱에서 사용자가 하나의 공식 시나리오를 선택해 사건을 플레이할 수 있게 한다.

핵심 경험:

```text
사건 선택
→ 사건 브리핑 확인
→ 증거 카드 확인
→ 용의자 심문
→ 시간별 증거 해금
→ 힌트 확인
→ 최종 추리 제출
→ 결과 해설 확인
```

### 3.2 1차 MVP 확장 목표

유저가 직접 커스텀 시나리오를 제작하고, AI 검증을 거쳐 공개할 수 있게 한다.

핵심 경험:

```text
커스텀 시나리오 생성
→ 용의자/증거/힌트/정답 직접 작성
→ AI 시나리오 검증
→ 공개/비공개 설정
→ 다른 유저가 플레이
```

### 3.3 후속 플랫폼 목표

인기 커스텀 시나리오를 공유하고, 플레이 수/평점/리뷰/북마크 기반으로 시나리오 라이브러리를 구성한다.

## 5. 핵심 게임 플로우

### 5.1 공식 시나리오 플레이

```text
1. 사용자가 앱을 실행한다.
2. 홈 또는 시나리오 라이브러리에서 공식 시나리오를 선택한다.
3. 시나리오 상세 화면에서 난이도, 예상 플레이 시간, 용의자 수, 증거 수를 확인한다.
4. 사건 브리핑을 읽는다.
5. 탐정 대시보드로 이동한다.
6. 현장 정보와 초기 증거를 확인한다.
7. 용의자 목록에서 용의자를 선택해 심문한다.
8. 시간이 지나거나 조건을 만족하면 추가 증거가 해금된다.
9. 힌트를 사용할 수 있다.
10. 사용자는 최종 추리를 제출한다.
11. 시스템은 정답과 비교해 점수, 등급, 해설을 제공한다.
```

### 5.2 커스텀 시나리오 제작

```text
1. 사용자가 제작 탭으로 이동한다.
2. 사건 배경, 유형, 난이도, 용의자 수를 선택한다.
3. 사용자는 사건 개요, 용의자, 증거, 힌트, 정답을 직접 작성한다.
4. AI 초안 생성은 2차 기능으로 선택 제공한다.
5. AI 검증을 실행한다.
6. 검증 결과에 따라 부족한 증거, 논리 오류, 난이도 문제를 수정한다.
7. 공개 범위를 설정한다.
8. 시나리오를 등록한다.
```

### 5.3 커스텀 시나리오 플레이

```text
1. 사용자가 시나리오 라이브러리에서 커스텀 시나리오를 선택한다.
2. 공식 시나리오와 동일한 플레이 구조로 진행한다.
3. 플레이 완료 후 평점과 리뷰를 남길 수 있다.
4. 스포일러가 포함된 리뷰는 접어서 표시한다.
```

## 7. AI 동작 원칙

### 7.1 AI가 하는 일

```text
사건 초안 생성
용의자 페르소나 생성
증거 설명 생성
힌트 생성
커스텀 시나리오 검증
AI 용의자 심문 응답
최종 추리 채점
사건 해설 생성
```

### 7.2 AI가 하면 안 되는 일

```text
설정에 없는 사실 생성
정답 선공개
범인 여부 직접 공개
증거 없이 자백
시나리오와 충돌하는 답변
해금되지 않은 비밀 공개
너무 장황한 답변 생성
```

### 7.3 AI NPC 답변 원칙

AI 용의자는 다음 원칙을 따른다.

```text
1. 답변은 1~2줄로 제한한다.
2. 현재 공개된 정보와 답변 정책 안에서만 말한다.
3. 설정에 없는 사실은 만들지 않는다.
4. 해금되지 않은 비밀은 말하지 않는다.
5. 결정적 증거가 제시되기 전까지 자백하지 않는다.
6. 범인 여부는 직접 말하지 않는다.
7. 질문에 답할 수 없으면 기억나지 않는다, 잘 모르겠다, 확인할 수 없다고 답한다.
```

### 7.4 범인 정보 관리 원칙

가장 중요한 원칙:

```text
AI 용의자에게 “네가 범인이다”라는 정보를 직접 주지 않는다.
범인 정보는 백엔드의 secret 데이터로 관리한다.
AI에게는 현재 장면에서 말해도 되는 정보와 답변 정책만 전달한다.
```

나쁜 방식:

```text
너는 사실 범인이다.
하지만 말하지 마라.
```

좋은 방식:

```text
현재 상태: 카페 결제 증거가 아직 공개되지 않음
답변 정책: 커피를 산 적 없다고 부인한다.
사용자 질문: 22시 이후 어디에 있었습니까?
```

AI는 위 정책만 기반으로 짧게 답변한다.

## 14. 리스크와 대응

### 14.1 사건 품질이 낮으면 재미가 없다

대응:

```text
공식 시나리오는 사람이 검수한다.
AI 생성 시나리오는 AI 검증 단계를 거친다.
유저 평점과 완료율로 품질 낮은 시나리오를 걸러낸다.
```

### 14.2 AI가 정답을 누설할 수 있다

대응:

```text
AI에게 범인 정보를 직접 주지 않는다.
백엔드에서 secret을 관리한다.
AI에게는 현재 말해도 되는 정보만 전달한다.
답변을 1~2줄로 제한한다.
```

### 14.3 커스텀 시나리오 품질이 들쭉날쭉할 수 있다

대응:

```text
AI 시나리오 검증 기능 제공
공개 전 최소 조건 검사
평점 / 리뷰 / 신고 기능 제공
운영진 추천 시나리오 제공
```

### 14.4 추리게임은 1회성 콘텐츠다

대응:

```text
사건 라이브러리 제공
커스텀 시나리오 공유
인기 시나리오 랭킹
AI 시나리오 생성(2차)
시나리오 변주 기능 제공
```

### 14.5 실제 사건 모티브의 윤리 문제

대응:

```text
실제 사건을 그대로 재현하지 않는다.
인물, 장소, 관계, 범행 방식은 충분히 각색한다.
민감한 실제 사건, 최근 사건, 특정 가능한 사건은 사용하지 않는다.
```

## 17. 개발용 AI가 지켜야 할 원칙

개발 보조 AI는 다음 원칙을 지켜야 한다.

```text
1. 이 프로젝트는 Android 앱 + Spring Boot 백엔드 구조를 전제로 한다.
2. AI 용의자에게 범인 정보를 직접 전달하지 않는다.
3. 범인, 정답, 핵심 비밀은 백엔드 secret으로 관리한다.
4. 심문 응답은 현재 공개 정보와 response policy 기반으로 생성한다.
5. AI 답변은 1~2줄로 짧게 제한한다.
6. 추리게임의 재미는 증거 조합과 모순 발견에서 나오도록 설계한다.
7. 단순 채팅앱처럼 구현하지 않는다.
8. 커스텀 시나리오 플랫폼 기능을 고려해 도메인을 설계한다.
```

## 18. 개발용 AI가 하면 안 되는 것

```text
1. AI NPC에게 “너는 범인이다”라는 정보를 직접 넘기는 코드 작성 금지
2. AI가 설정에 없는 사실을 만들어내는 구조 금지

6. 커스텀 시나리오를 단순 텍스트 하나로 저장하는 구조 금지
7. 스포일러 리뷰 관리 없이 리뷰를 공개하는 구조 금지
```

## 20. 최종 요약

CaseLab AI는 Android 기반 AI 추리게임 앱이다.

사용자는 탐정이 되어 사건 브리핑, 현장 정보, 증거 카드, 타임라인을 확인하고, AI 용의자들을 심문해 범인·동기·범행 방법을 추리한다.

서비스는 제작진이 만든 공식 시나리오뿐 아니라, 유저가 직접 사건을 만들고 공유할 수 있는 커스텀 시나리오 플랫폼을 제공한다.

핵심 설계 원칙은 다음과 같다.

```text
AI는 용의자 NPC 역할만 한다.
범인 정보와 핵심 비밀은 백엔드가 관리한다.
AI에게는 현재 말해도 되는 정보만 전달한다.
사건은 Case Graph로 구조화한다.
게임 재미는 증거 조합과 모순 발견에서 나온다.
```
