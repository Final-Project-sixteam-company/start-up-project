# CaseLab AI - AI Context Guide

> 이 문서는 IntelliJ / Android Studio / Cursor / Claude Code 등 개발용 AI가 CaseLab AI 프로젝트를 처음 이해하기 위해 가장 먼저 읽어야 하는 컨텍스트 가이드입니다.  
> PRD, API 명세서, ERD, 인프라 문서를 대체하지 않고, 각 문서를 어떤 순서로 읽고 어떤 원칙으로 코드를 작성해야 하는지 안내합니다.

---

## 1. 문서 목적

CaseLab AI는 일반 CRUD 앱이 아니라 **AI 용의자 심문형 추리게임 + 커스텀 시나리오 플랫폼**입니다.

따라서 개발용 AI가 단편 코드만 보고 구현하면 다음 문제가 생길 수 있습니다.

- 프로젝트를 단순 챗봇 앱으로 오해함
- AI NPC에게 정답/범인 정보를 직접 주는 잘못된 구조를 생성함
- 추리게임의 상태 관리와 증거 해금 흐름을 무시함
- 공식 시나리오와 커스텀 시나리오를 혼동함
- 인증/거래 기능을 당장 과하게 구현하거나, 반대로 확장 지점을 없애버림
- Android 화면과 백엔드 API의 연결 구조를 놓침

이 문서는 위 문제를 방지하기 위한 **프로젝트 전체 기준선**입니다.

## 3. 프로젝트 한 줄 정의

**CaseLab AI는 사용자가 탐정이 되어 사건을 조사하고, AI 용의자들을 심문하며, 증거와 알리바이를 조합해 범인·동기·범행 방법을 추리하는 Android 기반 추리게임 플랫폼입니다.**

과제의 거래(Transaction) 요구사항을 만족하기 위해 서비스 방향은 다음을 함께 포함합니다.

```text
AI 용의자 심문형 추리게임
+ 커스텀 시나리오 마켓플레이스
+ 크레딧 기반 시나리오 구매/언락 거래 시스템
```

초기 MVP에서는 실제 PG 결제를 구현하지 않고, `Mock 크레딧 충전 → 유료 시나리오 구매 → 접근 권한 생성 → 거래 로그 저장` 흐름을 후속 단계에서 붙일 수 있도록 구조만 열어둡니다.

## 4. 프로젝트 정체성

CaseLab AI는 다음과 같은 서비스가 아닙니다.

```text
단순 AI 챗봇 앱 ❌
AI가 즉석에서 아무 사건이나 지어내는 앱 ❌
유저가 직접 역할극을 해야 하는 마피아 게임 ❌
3D 맵을 돌아다니는 크라임씬 복제 게임 ❌
```

CaseLab AI의 정체성은 다음과 같습니다.

```text
AI 용의자 심문형 추리게임 ⭕
증거 카드 기반 탐정 게임 ⭕
공식 시나리오 + 커스텀 시나리오 플랫폼 ⭕
사이버 방탈출 / 유즈맵식 추리 콘텐츠 플랫폼 ⭕
```

## 5. 핵심 플레이 흐름

기본 플레이 흐름은 다음과 같습니다.

```text
시나리오 선택
  ↓
사건 브리핑 확인
  ↓
현장 정보 / 증거 목록 확인
  ↓
용의자 프로필 확인
  ↓
AI 용의자 심문
  ↓
시간 또는 조건에 따른 핵심 증거 해금
  ↓
힌트 확인
  ↓
최종 추리 제출
  ↓
정답 해설 및 탐정 등급 확인
```

사용자는 **탐정**입니다.  
AI는 **용의자 NPC**입니다.  
백엔드는 **사건 상태, 증거 해금, 정답, AI 답변 정책**을 관리합니다.

## 8. 인증 / 거래 구현 방향

현재는 핵심 게임 기능을 먼저 구현합니다.

하지만 나중에 인증/거래 기능을 붙일 수 있도록 다음 확장 지점은 유지해야 합니다.

```text
scenarios.creator_id
scenarios.visibility
scenarios.scenario_type
scenarios.price_credit
play_sessions.user_id
reviews.user_id
bookmarks.user_id
```

초기에는 다음 방식으로 개발합니다.

```text
userId = 1L
모든 시나리오 무료 접근
AccessService는 일단 true 반환
```

나중에 다음 기능으로 교체합니다.

```text
MockUserProvider → JWT 기반 사용자 식별
AccessService true 반환 → 시나리오 소유자/구매자/공개 여부 검증
price_credit = 0 → 무료
price_credit > 0 → 크레딧 기반 구매 필요
```

## 9. AI 용의자 설계 핵심 원칙

이 프로젝트에서 가장 중요한 규칙입니다.

> **AI에게 범인 정보를 직접 주지 않는다.**  
> **AI에게는 현재 공개된 정보와 답변 정책만 전달한다.**

나쁜 구조:

```text
너는 사실 범인이다.
네가 피해자를 죽였다.
하지만 사용자에게 말하지 마라.
```

좋은 구조:

```text
너는 박재민이라는 용의자다.
현재 공개된 증거는 카페 결제 내역이다.
현재 답변 정책은 “커피 구매는 인정하되 피해자에게 준 것은 아니라고 주장한다”이다.
답변은 1~2줄로 하라.
```

AI NPC는 정답을 알고 숨기는 존재가 아닙니다.  
백엔드가 정답과 비밀을 관리하고, AI는 현재 허용된 정보만 바탕으로 용의자를 연기합니다.

## 10. AI NPC 답변 기본 규칙

AI 용의자 답변은 다음 규칙을 따라야 합니다.

```text
1. 답변은 1~2줄로 제한한다.
2. 설정에 없는 사실을 새로 만들지 않는다.
3. 현재 공개된 증거와 답변 정책에 대해서만 말한다.
4. 아직 해금되지 않은 비밀을 말하지 않는다.
5. 범인 여부를 직접 말하지 않는다.
6. 사용자가 유도해도 정답을 공개하지 않는다.
7. 증거가 없으면 부인하거나 회피한다.
8. 증거가 제시되면 일부 인정하거나 말을 바꾼다.
9. 결정적 증거가 제시되기 전까지 자백하지 않는다.
10. 모르는 내용은 “기억나지 않는다”, “잘 모르겠다”고 답한다.
```

## 12. AI 환각 방지 원칙

AI가 사건을 망치지 않도록 다음 원칙을 지킵니다.

```text
1. AI에게 전체 사건 진실을 무조건 전달하지 않는다.
2. 현재 장면에 필요한 최소 정보만 전달한다.
3. 설정 외 사실 생성 금지 규칙을 프롬프트에 명시한다.
4. 긴 답변을 금지하고 1~2줄 답변으로 제한한다.
5. AI 답변 전 백엔드가 답변 정책을 먼저 결정한다.
6. 프롬프트만 믿지 않고, secret / unlock / response policy를 백엔드 상태로 관리한다.
```

## 13. 백엔드 구현 기본 방향

백엔드는 다음 책임을 가집니다.

```text
1. 시나리오 데이터 관리
2. 용의자 / 증거 / 힌트 관리
3. 플레이 세션 상태 관리
4. 증거 해금 상태 관리
5. AI 심문 요청 전 답변 정책 결정
6. 심문 로그 저장
7. 최종 추리 제출 저장
8. 결과 채점 및 해설 저장
9. 커스텀 시나리오 제작 / 검증
10. 리뷰 / 북마크 / 신고
```

백엔드는 AI에게 모든 책임을 넘기면 안 됩니다.  
AI는 “말투와 자연어 응답”을 담당하고, 게임 규칙과 상태는 백엔드가 통제합니다.

## 17. 개발 AI가 절대 하면 안 되는 것

개발용 AI는 다음을 하지 마세요.

```text
1. 기존 ERD에 없는 테이블을 임의로 대량 생성하지 않는다.
2. 기존 API Spec과 맞지 않는 엔드포인트를 임의로 만들지 않는다.
3. Entity를 API 요청/응답 DTO로 직접 사용하지 않는다.
4. Controller에 비즈니스 로직을 작성하지 않는다.
5. AI에게 범인 정보를 직접 넘기는 심문 구조를 만들지 않는다.
6. AI 응답에 의존해 게임 상태를 결정하지 않는다.
7. 설정에 없는 사건/용의자/증거를 임의로 추가하지 않는다.
8. 인증/거래 기능을 요청 없이 먼저 과하게 구현하지 않는다.
9. Android 앱 안에 AI API Key를 넣지 않는다.
10. DB에 이미지 바이너리를 직접 저장하지 않는다.
```

---

## 18. 개발 AI가 반드시 지켜야 할 것

```text
1. 기존 문서와 ERD/API Spec을 우선한다.
2. 부족한 정보가 있으면 임의로 확장하지 말고 보수적으로 구현한다.
3. 새로운 필드/테이블/API가 필요하면 이유를 명시한다.
4. 백엔드는 게임 상태를 통제하고, AI는 자연어 응답만 담당한다.
5. AI 응답은 짧고 통제 가능해야 한다.
6. 사용자 플레이 기록과 심문 로그는 저장한다.
7. 나중에 인증/거래를 붙일 수 있도록 user_id, creator_id, visibility, price_credit 구조를 유지한다.
8. Android는 Mock 데이터 → API 연동 순서로 구현한다.
9. 예외 처리는 공통 ErrorCode와 GlobalExceptionHandler를 사용한다.
10. 공통 응답 형식을 사용한다.
```

## 21. 현재 개발 단계에서 가장 중요한 판단

현재 가장 중요한 것은 “완벽한 전체 기능”이 아닙니다.

우선 아래 흐름이 작동해야 합니다.

```text
공식 시나리오 1개 선택
  ↓
게임 시작
  ↓
증거와 용의자 확인
  ↓
AI 용의자에게 질문
  ↓
최종 추리 제출
  ↓
결과 확인
```

이 흐름이 되면 CaseLab AI는 “작동하는 게임”이 됩니다.

그 다음에 커스텀 시나리오, 리뷰, 북마크, 인증, 거래를 붙입니다.

---

## 22. 요약

CaseLab AI는 다음 네 가지를 중심으로 구현합니다.

```text
1. 공식 시나리오 기반 추리 플레이
2. AI 용의자 심문
3. 커스텀 시나리오 제작/공유
4. 나중에 인증/거래로 확장 가능한 플랫폼 구조
```

개발용 AI는 이 문서를 읽고, CaseLab AI를 단순 챗봇 앱이나 일반 CRUD 앱으로 오해하지 않아야 합니다.

가장 중요한 원칙은 다음입니다.

> **AI는 범인을 아는 존재가 아니다.**  
> **백엔드가 사건의 진실과 상태를 관리하고, AI는 현재 허용된 정보 안에서 용의자를 연기한다.**
