
## QA Method

이번 QA는 정답 문서나 seed를 보지 않고 진행했다.

진행 방식:

```text
1. Android 앱 초기화 후 온보딩/라이브러리 진입
2. 서월채 상세 화면 확인
3. 진행 중 세션 충돌(P002) 확인 및 기존 오래된 세션 abandon 후 신규 세션 생성
4. 앱 상세 화면에서 active session 진입 가능 여부 확인
5. 앱 진입이 막혀 동일 운영 API로 세션 내부 조회/심문 진행
6. 초기 증거 7개, 용의자 5명, 타임라인을 보고 추리 가설 수립
7. AI 심문 25회 진행
8. 해금된 증거만 기준으로 최종 추리 제출
9. 결과 화면 기준으로 플레이 실패 원인과 개선점 정리
```

플레이어 관점의 초기 추리 전략:

```text
1. 사건 구조를 "복약/물/와인 중 하나에 대한 개입"으로 가정
2. 21:05~21:40의 2층 동선 공백을 핵심 시간대로 설정
3. 약품 접근권, 침실 준비권, 보안 은폐권을 가진 용의자를 비교
4. 복약 알림/호출 패널/약품 보관함/보안 재동기화 로그를 시간순으로 대조
5. 가장 일관된 동기-수단-기회 조합을 최종 제출
```

## Good

### 1. 사건 컨셉은 명확함

`VIP 별장동`, `비공식 조정 회의`, `의식 저하`, `물병/약통/와인/2층 동선`이라는 재료는 추리 장르와 잘 맞는다.

좋았던 점:

```text
- 독살 미스터리로서 물/약/와인 후보가 직관적이다.
- 18:30~21:40 타임라인이 사건 구조를 잡는 데 도움이 된다.
- 용의자 5명 규모는 MVP 플레이에 적절하다.
- 초기 증거 7개만으로도 사건의 큰 축은 이해할 수 있다.
```

### 2. 시간 로그형 증거는 추리 퍼즐에 적합함

다음 증거들은 시간 비교형 퍼즐로 잘 작동할 수 있다.

```text
- 침실 복약 알림/스누즈 로그
- VIP 케어 호출 패널 로그
- 약품 보관함 개봉 로그
- 와인셀러 관리자 권한 카드 로그
- 보안 서버 재동기화 로그
- 케어 스테이션 접근 로그
```

특히 `복약 알림 -> 스누즈 -> 호출 패널 -> 발견` 순서는 사건 후반부를 좁히는 데 좋다.

### 3. 답변 길이 제약은 대체로 지켜짐

AI 답변은 대부분 1~2문장으로 유지됐다. 장황하게 늘어지는 문제는 크지 않았다.

## P0 Issues

### 1. 앱 상세 화면에서 active session 복구 경로가 막힘

상황:

```text
POST /api/play-sessions
-> 409 P002
-> details.activeSessionId = <activeSessionId>
```

기존 active session이 있으면 서버는 정상적으로 `activeSessionId`를 내려준다. 그러나 Android 상세 화면에서는 사용자가 왜 시작이 안 되는지 명확히 알 수 없었고, 새로 만든 active session <sessionId>가 있어도 상세 화면 CTA로 세션 내부 진입이 되지 않았다.

관찰:

```text
- 상세 화면의 "조사 시작" 버튼이 비활성처럼 보이거나 눌러도 전환되지 않음
- P002 active session 안내/이어하기/포기 후 새 시작 경로가 화면에 명확히 보이지 않음
- 라이브러리/기록 탭으로 우회하려 했으나 세션 내부로 들어가지 못함
```

개선안:

```text
P002 수신 시:
- "진행 중인 수사가 있습니다" 모달 표시
- "이어하기" -> GET /api/play-sessions/{activeSessionId}/dashboard 진입
- "기존 세션 포기 후 새로 시작" -> POST /api/play-sessions/{id}/abandon 후 POST /api/play-sessions
- abandon 실패/재생성 실패 시 명확한 에러 메시지 표시
```

### 2. 공개 API가 스포일러성 메타데이터를 노출함

용의자 목록 응답에서 `culpritEligible=false`가 포함되어 있었다.

문제:

```text
신규 유저가 API 응답만 보면 특정 인물을 시스템적으로 배제할 수 있다.
```

추가로, 초상 이미지 경로에도 역할성 힌트가 포함된다.

예:

```text
characters/WITNESS_...
```

개선안:

```text
- 플레이어용 API에서 culpritEligible 제거
- 플레이어용 API에서 importance/solution 관련 내부 메타 제거
- asset path에 WITNESS/CULPRIT/RED_HERRING 등 역할성 이름 사용 금지
- 운영 플레이 API와 admin/debug API를 분리
```

### 3. `includeLocked=true`로 잠긴 증거명 25개 전체가 노출됨

호출:

```http
GET /api/play-sessions/<sessionId>/evidences?includeLocked=true
```

결과:

```text
25개 증거 제목 전체가 반환됨
잠긴 증거의 제목만으로도 후반 핵심 방향을 추측할 수 있음
```

문제:

```text
includeLocked 파라미터가 일반 플레이 API에서 접근 가능하면, 클라이언트/사용자/네트워크 로그를 통해 잠긴 증거명이 새어 나갈 수 있다.
```

개선안:

```text
- 일반 플레이어 권한에서는 includeLocked=true 무시 또는 403
- 잠긴 증거는 placeholder만 반환
- includeLocked는 admin/debug 전용 endpoint로 분리
- FE가 includeLocked를 절대 호출하지 않는지 확인
```

### 4. AI가 타임라인상 불가능한 시각을 생성함

타임라인상 피해자는 21:40에 발견된다. 그런데 심문 중 일부 답변이 22:20, 22:30 침실 방문/복약 준비를 주장했다.

관찰 답변 예:

```text
질문: 어젯밤 10시 이후 피해자의 건강 상태나 복약 루틴을 직접 확인했나요?
답변: 22시 20분경 침실에 방문했습니다.

질문: 회의 후 침실 준비를 했다고 했는데, 피해자를 마지막으로 본 시각은?
답변: 22시 30분쯤 침실에 들어갔습니다.
```

문제:

```text
- 피해자가 21:40에 발견됐으므로 22:20/22:30의 정상 방문 진술은 사건 전 동선으로 성립할 수 없다.
- 유저가 시간대를 조금 잘못 물었을 때 AI가 "그때는 이미 발견 후입니다"라고 정정하지 않고 새 사실을 만들었다.
- 이 답변 때문에 QA 플레이어는 잘못된 용의자를 강하게 의심하게 됐다.
```

개선안:

```text
- ResponsePolicyResolver 또는 prompt context에 사건 기준 타임라인 hard guard 추가
- 발견 시각 이후의 질문에는 "그 시각에는 이미 발견 후였다"로 정정
- NPC가 모르는 시간은 "확인할 수 없다"로 제한
- 설정에 없는 구체 시각 생성 금지
- timeline event를 AI prompt에 더 명시적으로 전달
```

## P1 Issues

### 1. 핵심 질문에 대한 답변이 너무 자주 회피형으로 끝남

관찰 답변 예:

```text
"어떤 약품을 꺼냈는지는 처방 기록과 함께 확인해야 합니다."
"누가 먼저 도착했는지는 제가 도착했을 때 이미 다른 분이 계셨는지 확인해야 알 수 있습니다."
"출입 기록이나 CCTV 공백 여부는 장애 기록과 출입 로그를 함께 확인해야 합니다."
```

문제:

```text
- 답변이 틀리지는 않지만, 플레이어가 다음 행동을 결정할 정보가 부족하다.
- "다른 증거와 함께 봐야 한다"가 반복되는데, 어떤 증거를 봐야 하는지 명확히 말하지 않는다.
- 20회 심문 후에도 증거가 13/25에서 더 열리지 않아 진행감이 끊겼다.
```

개선안:

```text
각 NPC 답변에 최소 1개는 다음 단서 방향을 포함한다.
예:
- "그 시간은 호출 패널 로그와 비교해 보세요."
- "약품 보관함 개봉 로그의 두 시각이 중요합니다."
- "관련 서비스 체크리스트가 있으면 준비 시각을 확인할 수 있습니다."
```

주의:

```text
정답을 직접 주라는 뜻이 아니다.
플레이어가 다음으로 확인할 증거 범주를 알 수 있게 하자는 의미다.
```

### 2. 증거 설명에 핵심 판독값이 부족함

이미지에는 중요한 시각이 들어 있다.

관찰한 판독값:

```text
복약 알림: 21:15, 21:20, 21:25, 이후 보호된 로그
호출 패널: 21:37 환자 호출
약품 보관함: 21:07, 21:13 개봉
와인셀러: 20:48 관리자 카드 접근
보안 재동기화: 21:24:07, 40초
케어 스테이션: 상태 로그, 호출 패널 원본 로그
```

문제:

```text
- 모바일 화면에서는 이미지 속 작은 텍스트를 읽기 어렵다.
- description은 "다른 로그와 비교"라고 말하지만, 핵심 시각을 텍스트로 다시 적어주지 않는 경우가 많다.
- 사용자는 중요한 단서인지 분위기 이미지인지 구분하기 어렵다.
```

개선안:

```text
증거 상세에 "판독 결과" 필드를 추가한다.

예:
판독 결과:
- 21:15 복약 알림
- 21:20 스누즈
- 21:25 스누즈 2회
- 21:30/21:35 기록 보호

비교 대상:
- VIP 케어 호출 패널 로그
- 관련 물품과 컵
- 야간 약통
```

### 3. 추천 질문 API가 문서에는 있으나 운영에서는 404

문서상:

```http
GET /api/play-sessions/{sessionId}/recommended-questions
```

운영 호출 결과:

```text
404 C005 Resource not found
```

문제:

```text
- FE 문서/화면/서버 구현이 불일치한다.
- 힌트 API도 빈 배열이라, 막힌 유저가 다음 질문을 찾을 방법이 없다.
- 초반에는 정적 추천 질문이 있더라도 중반 증거 기반 추천이 없으면 13/25에서 멈출 수 있다.
```

개선안:

```text
- MVP에서 추천 질문 API를 구현하거나 문서에서 제거
- 최소한 FE local 추천 질문에 evidenceId/suspectId 기반 질문을 추가
- 증거 상세에서 "이 증거로 물어볼 질문" CTA 제공
```

### 4. 최종 추리 실패 원인이 게임 내에서 충분히 학습되지 않음

QA 플레이어는 해금된 13개 증거 기준으로 한 용의자를 지목했고, 점수는 D였다.

문제:

```text
- 최종 추리에 필요한 후반 증거 다수가 플레이 중 잠긴 상태로 남았다.
- 잠긴 증거를 어떻게 열어야 하는지 안내가 없었다.
- AI 답변의 잘못된 시간 생성 때문에 오답 확신이 강화됐다.
```

개선안:

```text
- 핵심 증거 unlock 조건을 "질문 횟수"가 아니라 명확한 플레이 행동과 연결
- 특정 증거 제시 후 관련 후속 증거가 열렸다는 피드백 표시
- 최종 추리 전 "아직 핵심 시간대 증거가 부족합니다" 같은 비스포일러 경고 제공
```

## P2 Issues

### 1. 용의자 기본 정보가 리스트/상세에서 더 풍부해야 함

현재 용의자 정보는 직무와 짧은 알리바이 중심이다.

개선안:

```text
각 용의자 카드에 다음을 분리 표시한다.
- 이해관계
- 접근 권한
- 주장 동선
- 확인해야 할 증거 유형
```

예:

```text
접근 권한: 처방/의료 기록
주장 동선: 간이진료실 -> 침실 -> 케어 스테이션
확인 증거: 보관함 로그, 알림 로그, 상태 로그
```

### 2. 타임라인은 API에서 제공되지만 앱 진입 실패로 확인 불가

API의 타임라인은 유용하다. 하지만 이번 Android QA에서는 active session 내부 화면 진입이 막혀 앱에서 타임라인 UX를 확인하지 못했다.

개선안:

```text
- active session 복구 경로 수정 후 타임라인 화면 재QA
- 타임라인에서 관련 증거로 바로 이동 가능하게 연결
- 사건 기준 시각(21:02, 21:15, 21:24, 21:37, 21:40)을 시각적으로 강조
```

### 3. `status` 필드가 빈 값처럼 보임

증거 응답에서 `status`가 화면 출력상 비어 있었다.

개선안:

